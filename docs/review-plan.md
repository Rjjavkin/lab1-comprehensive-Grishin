# План проведения Code Review для модуля `src/discount.py`

## 1. Цели ревью
* Проверка математической точности вычисления скидок и итоговой суммы корзины.
* Защита от финансового фрода (предотвращение отрицательной цены и превышения лимита максимальной скидки 30%).
* Проверка корректности очередности применения промокодов и бонусов уровня лояльности.

## 2. Измеримые критерии приемки
* **Отсутствие магических чисел:** все коэффициенты (`0.85`, `0.90`, `0.97`, `0.93`, `0.70`), порог корзины (`15000`) и фиксированные скидки (`500`) вынесены в именованные константы.
* **Валидация входных данных:** добавлена проверка на отрицательную сумму корзины (`cart_sum < 0`), корректность типа `promos` и допустимые значения `tier`.
* **Покрытие тестами (Unit Test Coverage):** не менее 85% (строго > 80%), включая граничные значения (`cart_sum == 15000`, пустой список промокодов, срабатывание потолка скидки 30%).
* **Соответствие линтеру:** 0 предупреждений и ошибок `flake8`.

## 3. Участники и роли
* **Автор кода (Developer):** разработчик микросервиса, устраняющий замечания и поддерживающий актуальность тестов.
* **Ревьюер 1 (Tech Lead / Code Owner):** проверка архитектуры, безопасности расчетов и соблюдения стандартов команды.
* **Ревьюер 2 (QA / Backend Engineer):** проверка граничных случаев и полноты модульных тестов.

## 4. Механизм эскалации при спорах
1. Если автор и ревьюер не приходят к согласию в комментариях PR в течение **4 рабочих часов**, организуется короткий созвон (до 15 минут).
2. Если спор касается бизнес-логики скидок, вопрос эскалируется **Product Owner'у** для фиксации требований в задаче.
3. Окончательное техническое решение при архитектурных разногласиях принимает **Tech Lead**.
